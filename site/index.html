Our case: more freedom for a custom experience, with responsibility for building and maintaining it. A repository gives us a shared source and history; permissions, structure, and protocols make it usable.

Business case · 3 min. Do not claim HTML replaces every platform capability. GitHub is enough as the shared source base for this workshop; it does not automatically provide editing tools, hosting, authentication, or a database. The phone gains a product brief: log an activity and see progress.

09 / BRING THE WORK BACK TOGETHER

One improvement.
Back in main.

After review, merge the change. Then delete the completed feature branch.

Open the pull request and complete the review first.

Deleting the merged branch removes its name. The merged work stays in main’s history.

If edits conflict, people resolve the intended result before merging. A clean merge still needs testing.

Merge · 3 min. Merge only becomes available after the earlier review. A merged branch’s name can be removed without removing the history reachable from main. Point out the phone switching from branch preview to main. This diagram uses a merge commit; squash and fast-forward are other strategies.

11 / GIVE EVERY ACTION A RECORD

Use the phone. Each activity becomes structured data: who, what, when, and how long.

Log an activity on the phone to create a row.

This demo mirrors browser memory into a table. No real API or remote database is connected.

Records · 3 min. Log two different activities. Each row has an ID and time; minutes remain numbers. A real app sends a request to an API that validates data and permissions before writing to a database. A database does not automatically push content into HTML: the app must request it or subscribe to updates.
12 / KEEP THE RECORD, RELOAD THE VIEW

Close the screen.
Keep the progress.

Enable saving, log an activity, then reload the phone. The records return and rebuild the interface.

Saving is off. The phone currently uses temporary memory.

Saved records→JavaScript→HTML view
Same code + current data = the current experience.

Workshop simulation: localStorage on this browser, not a shared database. A real database lives independently of a visitor’s device, with an API and access rules. GitHub Pages serves static files; those services must be provided separately.

Persistence · 3 min. Enable saving before reloading. This keeps records on this device only. For a real backend, show a write request followed by a read request. Never place privileged database credentials in public source or browser code. UI edits may require deployment; runtime data changes can appear on the next request without changing the code.
