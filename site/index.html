01 / THE IDEA From description to experience

describe demonstrate it?

A document explains an idea. An interactive prototype lets us explore what happens when someone uses it.

HTML

The content and its structure.

<button>Contribute</button>
CSS

The visual language and motion.

color · layout · animation
JavaScript

The behavior and changing state.

click → update → feedback
The browser brings all three together.“HTML” in our title is shorthand for this web toolkit.
Frame the metaphor · 3 minEnglish helps us communicate intent. Web prototypes give us another medium for expressing it. HTML supplies semantic structure; CSS controls presentation; JavaScript adds programmable behavior. A prototype helps test assumptions; it does not establish that a design works for real users.

A USEFUL STARTING PROMPT

Create a single, self-contained HTML prototype for a new community member making their first contribution. Use embedded CSS and JavaScript. Make one complete interaction work. Explain your assumptions, keep controls keyboard-accessible, and include a reset. Use fictional content and no external services.

Add your chosen Core Drive, motivation hypothesis, and acceptance criteria before generating.
Your live workflow · 5 minSwitch to your preferred AI tool and demonstrate the prompt if time allows. Add a specific motivation hypothesis. Narrate one inspection and one revision. If generation is slow, return to the working demos here. Mixed tools are fine; everyone can use the same brief and output format.

Contribute & swap · 10 minBefore the session: create the private repository, invite everyone, verify access, create pair folders, and prepare branch protection and contribution instructions. During the session: collect first versions via pull requests and merge before the swap. Receiving pairs start from the merged version and open a new pull request. Original authors review. 08 / SHARED PROTOCOLS Different tools. Shared expectations.

A repository holds files.
A protocol helps us collaborate.

BEFORE BUILDING

Make intent explicit.

Audience. Desired behavior. Motivation hypothesis. Constraints. What success looks like.

BEFORE SHARING

Check the experience.

Run the main interaction. Check keyboard access. Record what works and what remains uncertain.

BEFORE MERGING

Explain the change.

What changed? Why? How was it tested? What should the next person know?

Debrief: where did you have to guess?Which shared habit would have saved you time?
Debrief · 5 minAsk each pair to name one piece of missing context and one useful piece of context. Refine these working agreements with the team. Protocol means a shared way of working here, not MCP or another technical integration standard.
